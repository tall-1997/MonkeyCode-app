# 手机端 Agent 能力需求（记忆 / 定时任务 / 浏览器 GUI，云端+本地双模式）

## 简介

参考 OmniBot（开源手机端 AI Agent）的能力设计，为 MonkeyCode 手机端（Expo / React Native）增加三类 Agent 能力：长期记忆系统、定时/计划任务、浏览器 GUI 操作。三类能力同时支持**云端模式**（任务运行在 MonkeyCode 云 VM，复用现有 taskflow / codingmatrix agent 链路）与**本地模式**（手机本地执行，任务运行在设备内嵌的轻量 agent 环境），两种模式数据双向同步、可无缝切换。

## 术语

- **云 agent**：运行在 MonkeyCode 云端 VM 中的 coding agent（codex / claude / opencode），由现有 backend task 链路驱动。
- **本地 agent**：运行在手机端本地执行环境中的 agent，可在弱网/断网时独立完成推理与工具调用。
- **Agent 资源**：skills、plugins、MCP 服务器、rules 的总称，现有 backend `agentresource` 已支持三级（global/team/user）解析与下发。
- **长期记忆**：跨任务、跨会话持久化的用户偏好、项目事实与历史决策，支持向量化检索。
- **短期记忆**：当前任务会话内的上下文，随任务结束归档或进入长期记忆。
- **计划任务**：由用户或 Agent 创建、按 cron 表达式或相对时间周期触发、执行子代理完整任务流的任务。
- **浏览器 GUI 操作**：Agent 驱动浏览器进行视觉化操作（点击、输入、滚动、截图、断言），用于任务执行中的页面操作与结果验证。
- **Embedding**：将文本映射为稠密向量，用于记忆的相似度检索。当前 backend 模型接口（openai_chat / openai_responses / anthropic）未覆盖 embedding 类型，需扩展。

## 需求

### 需求 1：长期记忆系统

**用户故事：** 作为手机端用户，我希望 Agent 记住我的偏好、项目事实和历史决策，以便跨会话保持一致并减少重复说明。

1. 系统 SHALL 提供长期记忆的写入能力，WHEN Agent 在任务执行中发现用户偏好或可复用结论时，系统 SHALL 将其沉淀为一条带标签与来源关联的记忆记录。
2. WHEN 用户或 Agent 开启新任务，系统 SHALL 依据任务内容检索相关长期记忆，并将检索结果注入任务上下文。
3. 系统 SHALL 为长期记忆提供向量化存储与相似度检索，检索质量 SHALL 依赖 embedding 模型，模型类型 SHALL 支持 `embedding` 类型（现有模型接口需扩展）。
4. 长期记忆 SHALL 按 scope 隔离，用户级记忆仅对所属用户可见，团队级记忆仅对团队内成员可见。
5. WHILE 任务处于执行中，Agent 产生的短期记忆 SHALL 随任务上下文存在，并在任务结束后由系统决定是否归档为长期记忆。
6. IF 记忆检索无相关结果，系统 SHALL 以空上下文继续任务，SHALL NOT 阻塞任务创建。
7. 系统 SHALL 提供记忆的管理接口，WHEN 用户查看、搜索或删除某条记忆，系统 SHALL 返回对应结果并同步生效于后续任务。
8. 本地模式下，长期记忆 SHALL 支持设备本地存储与云端存储双向同步，冲突 SHALL 以时间戳最新者为准。
9. 长期记忆 SHALL 在云端与本地各自维护独立向量库（双端各自向量库）：云端向量库承载团队级与全量用户级记忆，本地向量库承载设备常用记忆子集并支持离线检索，两端通过同步协议合并。

### 需求 7：浏览器统一控制层

**用户故事：** 作为平台开发者，我希望云端与本地两端使用统一的浏览器控制协议，以便复用操作编排与前端展示逻辑。

1. 系统 SHALL 定义统一的浏览器控制层协议，WHEN Agent 发起页面操作，系统 SHALL 通过该协议在云端 VM 或本地 WebView 上执行，并返回统一的截图、DOM 状态与断言结果。
2. 云端与本地 SHALL 共用同一套浏览器操作编排逻辑，IF 两端能力差异导致操作不可执行，系统 SHALL 返回统一的不可执行原因。
3. 浏览器控制层 SHALL 作为 Agent 的一个工具暴露，复用现有 skill/工具下发链路注入 agent 会话。

### 需求 2：定时 / 计划任务

**用户故事：** 作为手机端用户，我希望按计划周期触发 Agent 子任务，以便定时完成代码审查、文档生成、巡检等重复性工作。

1. 系统 SHALL 提供计划任务的创建能力，WHEN 用户创建计划任务，系统 SHALL 接受任务内容、触发时间或 cron 表达式、执行模式（云端/本地）作为输入。
2. WHEN 计划任务到达触发时间，系统 SHALL 创建一个子代理任务并执行用户预设的完整任务流，执行过程 SHALL 与普通任务一致。
3. 系统 SHALL 支持一次性计划与周期计划，周期计划 SHALL 使用 cron 表达式描述，cron 解析失败 SHALL 拒绝创建并返回可读错误。
4. 云端模式下的计划任务调度 SHALL 基于 backend 现有 Redis 延迟队列（`pkg/delayqueue`）实现，触发精度 SHALL 达到分钟级。
5. 本地模式下的计划任务调度 SHALL 基于手机系统任务调度能力（如 `expo-background-task` / `expo-notifications`）实现，WHEN 手机处于后台或省电状态，系统 SHALL 尽力在触发时间窗口内执行。
6. 计划任务 SHALL 支持启用/停用、查看下次触发时间、手动立即触发与删除，状态变更 SHALL 实时同步到云端与本地。
7. WHEN 计划任务执行结果产生，系统 SHALL 通过现有通知通道向用户推送结果摘要。
8. IF 计划任务执行失败，系统 SHALL 记录失败原因，SHALL 在下次触发时重试，并 SHALL 向用户展示最近一次执行结果。
9. 系统 SHALL 对计划任务提供每用户配额限制，超出配额 SHALL 拒绝创建并返回明确提示。

### 需求 3：浏览器 GUI 操作

**用户故事：** 作为手机端用户，我希望 Agent 能驱动浏览器操作页面并验证结果，以便完成需要与网页交互的开发与测试任务。

1. 云端模式下，Agent SHALL 在任务 VM 内驱动浏览器（基于现有 coding agent 的浏览器能力）进行打开页面、点击、输入、滚动、导航等操作，并获取页面截图与 DOM 信息。
2. 本地模式下，Agent SHALL 通过手机端内嵌浏览器组件（如 `react-native-webview` + 调试桥）执行页面操作，操作结果 SHALL 以截图与结构化状态返回。
3. WHEN Agent 完成一次页面操作，系统 SHALL 将操作结果（截图、状态、可执行断言结果）作为任务事件流的一部分返回给前端展示。
4. 浏览器操作产生的截图 SHALL 支持持久化保存，WHEN 用户打开任务详情，系统 SHALL 展示操作过程中的截图与页面状态。
5. 系统 SHALL 对浏览器操作设置安全边界，IF 页面地址不在用户授权范围或触发外部网络访问限制，系统 SHALL 拒绝操作并返回原因。
6. 浏览器 GUI 操作 SHALL 复用现有任务流消息通道（`TaskStreamTypeTaskEvent` 等），保持前端消息处理链路不变。

### 需求 4：云端 / 本地双模式执行

**用户故事：** 作为手机端用户，我希望同一任务既能在云端执行也能在本地执行，以便在弱网时继续工作。

1. 系统 SHALL 支持用户为任务显式选择执行模式（云端 / 本地），未选择时 SHALL 使用用户默认模式。
2. 同一任务领域模型 SHALL 在两种模式下保持一致，本地任务完成时 SHALL 将任务结果、文件变更与记忆同步回云端。
3. WHEN 云端任务与本地任务操作同一仓库，系统 SHALL 通过现有 git 链路合并变更，SHALL NOT 产生数据丢失。
4. 本地模式 SHALL 在设备上提供可用的本地执行环境，环境初始化失败时 SHALL 回退提示用户使用云端模式。
5. 两种模式 SHALL 共享同一 Agent 资源体系（skills / plugins / MCP / rules），资源解析在云端进行、结果下发到对应执行端。
6. 系统 SHALL 提供执行模式切换能力，WHEN 运行中任务切换模式，系统 SHALL 保留任务上下文并迁移执行状态。
7. 本地执行引擎 SHALL 基于选定的 coding agent CLI（如 opencode / codex）嵌入，WHEN 用户创建本地任务，系统 SHALL 在本地环境初始化并驱动该 CLI 执行任务。
8. 本地 agent 的任务编排、事件流与结果上报 SHALL 通过统一桥接层转译为现有任务流协议，云端任务链路 SHALL 感知到本地执行状态。

### 需求 5：手机端交互与展示

**用户故事：** 作为手机端用户，我希望在任务工作台内查看记忆、计划任务与浏览器操作过程，以便掌控 Agent 行为。

1. 手机端任务工作台 SHALL 展示当前任务的记忆注入摘要，WHEN 用户查看任务详情，系统 SHALL 说明本次任务使用了哪些记忆。
2. 手机端 SHALL 提供计划任务管理页面，WHEN 用户创建、编辑、启停或删除计划任务，系统 SHALL 实时反映在云端与本地。
3. 手机端 SHALL 在任务消息流中展示浏览器操作卡片，WHEN 用户点击卡片，系统 SHALL 展示操作截图与页面详情。
4. 手机端 SHALL 提供记忆管理入口，WHEN 用户浏览或删除记忆，系统 SHALL 同步更新云端记录。
5. 手机端 SHALL 在任务详情页展示执行模式标识，WHEN 任务在本地执行，系统 SHALL 展示本地环境状态与离线提示。

### 需求 6：安全与合规

**用户故事：** 作为平台管理员，我希望 Agent 的本地执行与浏览器操作受到安全约束，以便避免资源滥用与越权访问。

1. 本地执行 SHALL 遵循与云端一致的用户鉴权与团队权限模型，WHEN 本地 agent 调用后端 API，系统 SHALL 校验会话与 token。
2. 本地执行的浏览器操作与工具调用 SHALL 受限在用户授权范围内，超范围操作 SHALL 被拒绝。
3. 长期记忆 SHALL 在传输与存储时加密，本地存储 SHALL 使用系统安全存储，云端存储 SHALL 遵循现有数据保护策略。
4. 系统 SHALL 对本地执行产生的 token 用量、任务时长进行计量，WHEN 超出配额，系统 SHALL 限制继续执行。

## 本次范围外

- 手机端原生系统级操作（闹钟、日历、音频控制等手机硬件能力的深度绑定）。
- 本地 agent 的自训练或本地模型微调。
- 多设备之间的实时协同编辑。
- 浏览器 GUI 操作的非 Web 桌面应用自动化（原生 App 自动化）。
- 计划任务的秒级精准调度。
